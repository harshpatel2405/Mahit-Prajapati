C++ CLASS TEMPLATES - MID-LEVEL PRACTICE QUESTION

Question: Student and Teacher Record Management Using Class Templates

Create a C++ program using a class template to manage records for different types of users.

Requirements:

1. Create a class Student with the following members:
   - name
   - marks
   - A show() method to display student details.

2. Create a class Teacher with the following members:
   - name
   - subject
   - A show() method to display teacher details.

3. Create a class template Record<T> with the following functionality:
   - Store an object of type T.
   - Use a constructor to initialize the object.
   - Create a display() method that calls the object's show() method.

4. In the main() function:
   - Create a Student object with name "Rahul" and marks 85.
   - Create a Teacher object with name "Amit" and subject "C++".
   - Pass these objects to separate Record template objects.
   - Display both records using the template class.

EXPECTED OUTPUT:

----- Student Record -----
Name: Rahul
Marks: 85

----- Teacher Record -----
Name: Amit
Subject: C++

RULES:
1. Use template <class T>.
2. Do not use inheritance.
3. Do not use function templates.
4. Use constructors and public member functions.
5. Do not duplicate the display logic inside the Record class.

CHALLENGE:
Design the Record<T> class so that it works with both Student and Teacher without modifying the template class.

C++ PRACTICE QUESTION — CLASS TEMPLATES + OOP PILLARS
Difficulty: Mid-Hard

QUESTION: GENERIC BANKING MANAGEMENT SYSTEM

Develop a C++ program for a Banking Management System that uses Class Templates and all four pillars of OOP: Encapsulation, Abstraction, Inheritance, and Polymorphism.

REQUIREMENTS:

1. CLASS: BankAccount (Encapsulation + Abstraction)
- Declare accountNumber, accountHolder, and balance as private data members.
- Provide a constructor to initialize all account details.
- Provide public methods deposit(), withdraw(), and displayDetails().
- The balance must not be modified directly from outside the class.
- A withdrawal must not be allowed if the requested amount exceeds the available balance.

2. CLASS: SavingsAccount (Inheritance)
- Inherit publicly from BankAccount.
- Add a private data member interestRate.
- Provide a constructor to initialize account details and interest rate.
- Add a method calculateInterest() to calculate the interest on the current balance.
- Override displayDetails() to display account information and interest rate.

3. CLASS: CurrentAccount (Inheritance)
- Inherit publicly from BankAccount.
- Add a private data member overdraftLimit.
- Provide a constructor to initialize account details and overdraft limit.
- Override withdraw() to allow withdrawals up to the permitted overdraft limit.
- Override displayDetails() to display account information and overdraft limit.

4. RUNTIME POLYMORPHISM
- Declare displayDetails() as virtual in BankAccount.
- Store SavingsAccount and CurrentAccount objects through BankAccount pointers.
- Call displayDetails() using base-class pointers and demonstrate runtime polymorphism.
- Ensure that the correct derived-class method is called.

5. CLASS TEMPLATE: AccountManager<T>
- Create a class template named AccountManager<T>.
- Store an object of type T inside the template class.
- Initialize the object using a constructor.
- Create a display() method that calls the object's displayDetails() method.
- Create a processWithdrawal() method that calls the object's withdraw() method.
- Use the same template with SavingsAccount and CurrentAccount objects.

6. MAIN FUNCTION
- Create one SavingsAccount object:
  Account Number: 101
  Account Holder: Rahul
  Initial Balance: 10000
  Interest Rate: 5%

- Create one CurrentAccount object:
  Account Number: 102
  Account Holder: Amit
  Initial Balance: 5000
  Overdraft Limit: 2000

- Deposit 2000 into Rahul's account.
- Withdraw 3000 from Rahul's account.
- Withdraw 6000 from Amit's account.
- Attempt to withdraw 3000 more from Amit's account.
- Display both account details using AccountManager<T>.

EXPECTED BEHAVIOUR:

- Rahul's balance should be updated correctly after deposit and withdrawal.
- Amit should be allowed to withdraw beyond his balance within the overdraft limit.
- Amit's final withdrawal should be rejected because it exceeds the permitted overdraft limit.
- Each account should display its own specific details.
- The template should work with both derived classes without duplicating the AccountManager implementation.

RULES:
1. Use class templates, constructors, and access specifiers.
2. Demonstrate all four OOP pillars.
3. Use inheritance and function overriding.
4. Use virtual functions to demonstrate runtime polymorphism.
5. Do not use global variables.
6. Do not use STL containers.
7. Do not duplicate the AccountManager class for different account types.
8. Use proper validation and meaningful output messages.

CHALLENGE:
Explain why the template class can work with both SavingsAccount and CurrentAccount, and explain the difference between compile-time polymorphism through templates and runtime polymorphism through virtual functions.
